Expérimentation 02 : WSL 2 & Docker

Mise en place et validation d'un environnement Linux virtualisé sous Windows 11 avec Ubuntu et Docker Desktop.

1. Objectif de l'expérimentation

Cette expérimentation consiste à installer et vérifier un environnement de développement Linux sous Windows 11 à l'aide de WSL 2, puis à intégrer Docker Desktop afin d'exécuter des conteneurs.

Les objectifs techniques sont les suivants :

  • Installer et configurer WSL 2.
  • Déployer Ubuntu comme distribution Linux.
  • Installer Docker Desktop avec le moteur WSL 2.
  • Vérifier l'accès à Docker depuis Windows PowerShell et Ubuntu.
  • Exécuter un conteneur de validation avec l'image officielle Hello World.

2. Environnement de test

Configuration matérielle

  • Ordinateur : ASUS ROG Strix G16 (G614FM).
  • Processeur : AMD Ryzen 9 9955HX, 16 cœurs et 32 threads.
  • Mémoire vive : 32 Go DDR5.
  • Carte graphique : NVIDIA GeForce RTX 5060 Laptop GPU.
  • Système hôte : Windows 11 Famille.

Environnement logiciel

  • WSL : version par défaut 2.
  • Distribution Linux : Ubuntu 26.04.1 LTS.
  • Noyau Linux : 6.18.54.1-microsoft-standard-WSL2.
  • Docker Desktop : moteur utilisant WSL 2.
  • Docker Engine / CLI : Docker 29.9.2, build a82e528.
  • Docker Compose : version 5.6.1.
  • Architecture Linux : x86_64.

3. Procédure de déploiement

Étape 1 — Installation de WSL 2

WSL a été installé depuis Windows avec la commande suivante, exécutée dans PowerShell : 

wsl --install -d Ubuntu

Après le redémarrage de Windows, Ubuntu a été initialisé et un compte utilisateur Linux local a été créé.

Étape 2 — Vérification de WSL

La configuration a été contrôlée avec :

wsl --status
wsl --list --verbose

Ubuntu apparaît avec la version 2 de WSL. Docker Desktop utilise également une distribution interne appelée docker-desktop.

Étape 3 — Installation de Docker Desktop

Docker Desktop a été installé sous Windows avec le moteur WSL 2. L'installation a été réalisée en mode utilisateur, sans connexion obligatoire à un compte Docker.

Étape 4 — Vérification des outils Docker

Depuis PowerShell, les commandes suivantes ont été exécutées :

docker --version
docker compose version

La disponibilité de la commande Docker a ensuite été vérifiée directement depuis le terminal Ubuntu : 

docker --version

4. Tests et résultats observés

Test 1 — Vérification de WSL 2

Résultat : validé.

Ubuntu 26.04.1 LTS a démarré sous le noyau Linux 6.18.54.1-microsoft-standard-WSL2. La distribution est configurée pour fonctionner avec WSL 2.

Test 2 — Disponibilité de Docker dans Windows

Résultat : validé.

PowerShell a reconnu Docker 29.9.2 ainsi que Docker Compose 5.6.1.

Test 3 — Disponibilité de Docker dans Ubuntu

Résultat : validé.

La commande docker --version a également fonctionné dans le terminal Ubuntu.

Test 4 — Exécution d'un conteneur Hello World

Commande exécutée depuis PowerShell :

docker run hello-world

Résultat : validé.

Docker a téléchargé l'image hello-world:latest, créé et exécuté le conteneur. Le message de confirmation « Hello from Docker! » a été affiché.

5. Observations et limites techniques

  • WSL 2 permet d'exécuter un environnement Linux intégré à Windows sans remplacer le système hôte.
  • Docker Desktop fournit l'accès au moteur Docker depuis Windows et depuis la distribution Ubuntu configurée.
  • La distribution Ubuntu peut apparaître à l'état « Stopped » lorsqu'aucune session Linux n'est active. Cet état ne signifie pas que l'installation est défectueuse.
  • Le test Hello World confirme le fonctionnement élémentaire du moteur Docker, mais ne constitue pas un benchmark de performances.
  • Aucun test de déploiement d'une application multi-conteneurs avec Docker Compose n'a été réalisé dans cette expérimentation.

6. Conclusion

L'expérimentation 02 a permis de mettre en place un environnement Linux fonctionnel sous Windows 11 avec WSL 2, Ubuntu et Docker Desktop.

Les vérifications réalisées confirment que Docker est accessible depuis PowerShell et Ubuntu et qu'un conteneur de test peut être téléchargé et exécuté correctement.

Cet environnement constitue une base technique pour de futurs travaux sur les conteneurs, les services web, les infrastructures locales et les environnements de développement isolés.
