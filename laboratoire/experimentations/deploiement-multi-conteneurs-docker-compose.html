TAKOUBAKOY LAB — EXPÉRIMENTATION 04

Déploiement multi-conteneurs
Docker Compose

Orchestration d'une application WordPress et d'une base de données MariaDB, avec réseau privé et volumes persistants.

OBJECTIF

1. Objectif de l'expérimentation

Cette expérimentation vise à déployer une application web composée de plusieurs services avec Docker Compose.

L'architecture repose sur deux conteneurs distincts : WordPress pour l'application web et MariaDB pour le stockage des données.

Les objectifs sont de vérifier le démarrage coordonné des services, leur communication sur un réseau privé, l'accès web local et la persistance des données après arrêt et redémarrage des conteneurs.

ENVIRONNEMENT

2. Configuration technique

  • Système hôte : Windows 11 Famille.
  • Terminal : Windows PowerShell 5.1.
  • Plateforme : Docker Desktop avec moteur WSL 2.
  • Docker Compose : version 5.6.1.
  • Base de données : MariaDB 11.4.
  • Application web : WordPress avec PHP 8.3 et Apache.
  • Réseau : bridge privé géré par Docker Compose.
  • Port publié : 127.0.0.1:8081 vers le port 80.
  • Stockage : deux volumes Docker nommés.

ARCHITECTURE

3. Architecture multi-conteneurs

Docker Compose orchestre deux services indépendants reliés au même réseau privé. 

Windows 11
    |
    | http://127.0.0.1:8081
    |
Docker Desktop / WSL 2
    |
    +-- Réseau : experiment-04-compose_lab-network
          |
          +-- WordPress
          |     takoubakoy-wordpress
          |     PHP 8.3 / Apache
          |     Port interne : 80
          |     Volume : wordpress_data
          |
          +-- MariaDB
                takoubakoy-db
                MariaDB 11.4
                Port interne : 3306
                Volume : db_data

WordPress communique avec MariaDB en utilisant le nom du service database sur le réseau Docker. Le port 3306 n'est pas publié sur l'hôte Windows.

L'accès web est limité à l'adresse de boucle locale 127.0.0.1 sur le port 8081.

PROCÉDURE

4. Déploiement du laboratoire

4.1 — Vérification de Docker Compose

docker compose version

Résultat observé : Docker Compose version 5.6.1.

4.2 — Préparation du dossier

Un dossier indépendant a été créé pour isoler cette expérimentation des précédents laboratoires. 

New-Item -ItemType Directory -Force -Path "$HOME\TAKOUBAKOY-LAB\experiment-04-compose"

Set-Location "$HOME\TAKOUBAKOY-LAB\experiment-04-compose"

4.3 — Configuration Docker Compose

Le fichier compose.yaml définit les deux services, leur réseau privé et leurs volumes persistants. 

services:
  database:
    image: mariadb:11.4
    container_name: takoubakoy-db
    restart: unless-stopped
    environment:
      MARIADB_DATABASE: wordpress
      MARIADB_USER: wpuser
      MARIADB_PASSWORD: [MOT_DE_PASSE_DE_TEST]
      MARIADB_ROOT_PASSWORD: [MOT_DE_PASSE_ROOT_DE_TEST]
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - lab-network

  wordpress:
    image: wordpress:php8.3-apache
    container_name: takoubakoy-wordpress
    restart: unless-stopped
    depends_on:
      - database
    ports:
      - "127.0.0.1:8081:80"
    environment:
      WORDPRESS_DB_HOST: database:3306
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: [MOT_DE_PASSE_DE_TEST]
      WORDPRESS_DB_NAME: wordpress
    volumes:
      - wordpress_data:/var/www/html
    networks:
      - lab-network

networks:
  lab-network:
    driver: bridge

volumes:
  db_data:
  wordpress_data:

Les mots de passe de laboratoire sont volontairement remplacés par des indications dans ce rapport. Les identifiants réels ne sont pas publiés.

4.4 — Validation de la configuration

docker compose -f "$HOME\TAKOUBAKOY-LAB\experiment-04-compose\compose.yaml" config

Résultat : la configuration a été interprétée correctement. Les deux services, le réseau et les volumes ont été reconnus.

4.5 — Téléchargement et démarrage

docker compose -f "$HOME\TAKOUBAKOY-LAB\experiment-04-compose\compose.yaml" up -d

Les images mariadb:11.4 et wordpress:php8.3-apache ont été téléchargées. Le réseau et les volumes ont été créés, puis les deux conteneurs démarrés.

4.6 — Vérification des services

docker compose -f "$HOME\TAKOUBAKOY-LAB\experiment-04-compose\compose.yaml" ps

Résultat observé : les deux conteneurs sont à l'état Up. WordPress publie le port 8081 sur 127.0.0.1. MariaDB reste accessible uniquement dans le réseau Docker.

RÉSULTATS

5. Tests et vérifications

Test 1 — Validation de la configuration

La commande docker compose config a confirmé la reconnaissance des services database et wordpress, du réseau bridge et des deux volumes.

Résultat : configuration validée.

Test 2 — Démarrage multi-conteneurs

Les images ont été téléchargées et les conteneurs takoubakoy-db et takoubakoy-wordpress ont démarré.

Résultat : démarrage réussi.

Test 3 — Communication WordPress et MariaDB

L'installation de WordPress a atteint l'écran de sélection de langue, puis le formulaire d'installation initiale.

L'installation et la création du site ont abouti, ce qui confirme que WordPress a pu communiquer avec sa base de données MariaDB.

Résultat : communication entre services validée.

Test 4 — Accès HTTP local

L'adresse http://127.0.0.1:8081 a été ouverte dans Microsoft Edge.

L'écran d'installation de WordPress s'est affiché, puis le site public et son tableau de bord ont été accessibles.

Résultat : accès web local validé.

Test 5 — Authentification administrateur

Le compte labadmin a été créé lors de l'installation. Après une perte du mot de passe initial, l'accès a été rétabli directement dans MariaDB, puis le mot de passe administrateur a été changé depuis l'interface WordPress.

Résultat : accès administrateur rétabli et sécurisé pour la suite de l'expérimentation.

Test 6 — Arrêt contrôlé des services

docker compose -f "$HOME\TAKOUBAKOY-LAB\experiment-04-compose\compose.yaml" stop

Résultat observé : WordPress et MariaDB ont été arrêtés. Les volumes n'ont pas été supprimés.

Test 7 — Redémarrage des services

docker compose -f "$HOME\TAKOUBAKOY-LAB\experiment-04-compose\compose.yaml" start

Résultat observé : les deux conteneurs ont redémarré. Leur état Up a été confirmé avec docker compose ps.

Test 8 — Vérification de la persistance

Après redémarrage, le tableau de bord WordPress était toujours accessible. Le compte labadmin et son nouveau mot de passe fonctionnaient.

Résultat : persistance de l'installation et des données du compte administrateur validée.

ANALYSE

6. Observations et limites

  • Docker Compose simplifie le déploiement coordonné de plusieurs services à partir d'un seul fichier.
  • Le réseau privé permet à WordPress de joindre MariaDB en utilisant le nom du service database.
  • La publication sur 127.0.0.1:8081 limite l'accès web à la machine hôte.
  • Les volumes nommés séparent les données persistantes du cycle de vie des conteneurs.
  • La commande stop conserve les conteneurs et les volumes. La commande start permet de les redémarrer.
  • La directive depends_on ordonne le démarrage des services, mais ne garantit pas à elle seule que MariaDB soit prête à accepter les connexions.
  • Aucun test de sauvegarde et de restauration des volumes, de haute disponibilité ou de charge n'a été réalisé.
  • Les identifiants de test ne doivent pas être réutilisés dans un environnement de production.

CONCLUSION

7. Conclusion technique

L'expérimentation 04 confirme le fonctionnement d'une application multi-conteneurs orchestrée avec Docker Compose.

WordPress et MariaDB ont été déployés sur un réseau privé, puis testés à travers l'installation de l'application et l'accès depuis le navigateur.

L'arrêt et le redémarrage des services ont permis de vérifier que les données associées aux volumes persistants étaient conservées.

Cette expérimentation constitue une base pratique pour comprendre l'orchestration de services, la séparation entre application et base de données et la gestion du stockage dans une infrastructure conteneurisée.
